# Автоматическая сводка рейдов

Серверный сбор включается настройкой `MADHOUSE_GLOBAL_RAIDS_CHAT_ID` в окружении Wiki. Укажите публичное имя канала, например `@madhouse_wiki_raids`, или его отрицательный числовой ID. При `MADHOUSE_GLOBAL_RAIDS_PUBLISHER=mtproto` сводку публикует и редактирует подключённый через MTProto Premium-аккаунт, имеющий права на публикацию и редактирование сообщений в канале. При отсутствии этого параметра используется Telegram-бот (`TELEGRAM_BOT_TOKEN`). Настройка и запуск выпуска выполняются отдельно.

Сервер использует общий с TMA опрос входящих приглашений доступных подключённых аккаунтов. Глобальная сводка не запрашивает детали боёв. Опрос повторяется не раньше чем через 30 секунд после завершения предыдущего; занятый или недоступный аккаунт пропускается до следующей попытки. Несколько приглашений на один `battleId` учитываются как одно наблюдение. Ведущий определяется по ID из приглашения; имя отправителя используется только при совпадении идентификаторов. Неизвестный ведущий отображается как «Игрок №ID».

Активный рейд появляется при трёх или более замеченных различных боях за последние два часа, как в TMA. Сводка использует сохранённую историю наблюдений TMA для рейдов с доступным приглашением. Счётчик «Замечено боёв» охватывает всю наблюдаемую серию. В канале показываются только незавершённые рейды с десятью или более замеченными боями; строки упорядочены по возрастанию этажа и отделения. Ведущий указывается только по подтверждённому username, при его отсутствии ставится прочерк. Статусы рассчитываются по свежим приглашениям и времени последнего наблюдения: меньше трёх минут — «Идёт», с трёх до десяти — «Ждёт», с десяти до тридцати — «Пауза», с тридцати — «Завершён». При отсутствии свежих данных после первых трёх минут показывается «Нет данных». Они не подтверждают фактическое завершение боя. В течение дня сообщение с настоящей таблицей Telegram Rich Messages редактируется каждую минуту. В полночь МСК создаётся новая сводка, а данные прошлого дня удаляются; продолжающиеся серии сохраняют счётчик и необходимую для дедупликации информацию о текущем приглашении. Данные сводки хранятся в зашифрованной таблице базы автоматизации.

Перед отправкой нового сообщения сервер сохраняет контрольную запись. Если ответ Telegram потерян, автоматическая повторная отправка блокируется, поскольку сообщение могло быть создано. Для восстановления оператор должен сначала проверить канал и вручную сверить состояние; без этого нельзя безопасно отправлять повторно. Успешные изменения существующего сообщения можно повторять. Сообщение ограничивается по длине; при переполнении указывается количество оставшихся строк. Клан показывается только при наличии проверенных данных; в текущей версии он не определяется.

В режиме MTProto статусы используют анимированные точки из набора `iconemoji1`. Для публикации нужен действующий Premium и сохранённая серверная Telegram-сессия. При недоступной сессии или отсутствии Premium публикация ждёт восстановления и не переключается на бота: Bot API может молча удалить custom emoji в канале.
