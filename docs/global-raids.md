# Автоматическая сводка рейдов

Серверный сбор включается только при настройке `MADHOUSE_GLOBAL_RAIDS_CHAT_ID` в окружении Wiki и работающем Telegram-боте (`TELEGRAM_BOT_TOKEN`). Укажите публичное имя канала, например `@madhouse_wiki_raids`, или его отрицательный числовой ID. Пока параметр отсутствует, сбор и публикация выключены. Бота необходимо добавить в канал администратором с правом публикации сообщений. Бот редактирует только свои сообщения. Настройка и запуск выпуска выполняются отдельно.

Сервер использует общий с TMA опрос входящих приглашений доступных подключённых аккаунтов. Глобальная сводка не запрашивает детали боёв. Опрос повторяется не раньше чем через 30 секунд после завершения предыдущего; занятый или недоступный аккаунт пропускается до следующей попытки. Несколько приглашений на один `battleId` учитываются как одно наблюдение. Ведущий определяется по ID из приглашения; имя отправителя используется только при совпадении идентификаторов. Неизвестный ведущий отображается как «Игрок №ID».

Активный рейд появляется при трёх или более замеченных различных боях за последние два часа, как в TMA. Сводка использует сохранённую историю наблюдений TMA для рейдов с доступным приглашением. Счётчик «Замечено боёв» охватывает всю наблюдаемую серию. Статусы рассчитываются по свежим приглашениям и времени последнего наблюдения; при недостатке данных отображается отметка «данные устарели». Они не подтверждают фактическое завершение боя. В течение дня сообщение с настоящей таблицей Telegram Rich Messages редактируется каждую минуту. В полночь МСК создаётся новая сводка, а данные прошлого дня удаляются; продолжающиеся серии сохраняют счётчик и необходимую для дедупликации информацию о текущем приглашении. Данные сводки хранятся в зашифрованной таблице базы автоматизации.

Перед отправкой нового сообщения сервер сохраняет контрольную запись. Если ответ Telegram потерян, автоматическая повторная отправка блокируется, поскольку сообщение могло быть создано. Для восстановления оператор должен сначала проверить канал и вручную сверить состояние; без этого нельзя безопасно отправлять повторно. Успешные изменения существующего сообщения можно повторять. Сообщение ограничивается по длине; при переполнении указывается количество оставшихся строк. Клан показывается только при наличии проверенных данных; в текущей версии он не определяется.
