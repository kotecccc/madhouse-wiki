# Автоматическая сводка рейдов

Серверный сбор включается настройкой `MADHOUSE_GLOBAL_RAIDS_CHAT_ID` в окружении Wiki. Укажите публичное имя канала, например `@madhouse_wiki_raids`, или его отрицательный числовой ID. При `MADHOUSE_GLOBAL_RAIDS_PUBLISHER=mtproto` сводку публикует и редактирует подключённый через MTProto Premium-аккаунт, имеющий права на публикацию и редактирование сообщений в канале. При отсутствии этого параметра используется Telegram-бот (`TELEGRAM_BOT_TOKEN`). Настройка и запуск выпуска выполняются отдельно.

Сервер использует общий с TMA опрос входящих приглашений доступных подключённых аккаунтов. Глобальная сводка не запрашивает детали боёв. Опрос повторяется не раньше чем через 30 секунд после завершения предыдущего; занятый или недоступный аккаунт пропускается до следующей попытки. Несколько приглашений на один `battleId` учитываются как одно наблюдение. Ведущий определяется по ID из приглашения; имя отправителя используется только при совпадении идентификаторов. Если имя ведущего не удалось достоверно определить по приглашениям, используется «Игрок №ID».

Активный рейд появляется при трёх или более замеченных различных боях за последние два часа, как в TMA. Сводка использует сохранённую историю наблюдений TMA для рейдов с доступным приглашением. Счётчик «Замечено боёв» охватывает всю наблюдаемую серию. В канале показываются только незавершённые рейды с десятью или более замеченными боями; строки упорядочены по возрастанию этажа и отделения. Ведущий указывается по подтверждённому username или, если его нет, по игровому нику, полученному из приглашений для того же ID. Значение оформляется настоящей кнопкой копирования. Статусы рассчитываются по свежим приглашениям и времени последнего наблюдения: меньше трёх минут — «Идёт», с трёх до десяти — «Ждёт», с десяти до тридцати — «Пауза», с тридцати — «Завершён». При отсутствии свежих данных после первых трёх минут показывается «Нет данных». Они не подтверждают фактическое завершение боя. В течение дня сообщение с настоящей таблицей Telegram Rich Messages редактируется каждую минуту. В полночь МСК создаётся новая сводка, а данные прошлого дня удаляются; продолжающиеся серии сохраняют счётчик и необходимую для дедупликации информацию о текущем приглашении. Данные сводки хранятся в зашифрованной таблице базы автоматизации.

Перед отправкой нового сообщения сервер сохраняет контрольную запись. Если ответ Telegram потерян, автоматическая повторная отправка блокируется, поскольку сообщение могло быть создано. Для восстановления оператор должен сначала проверить канал и вручную сверить состояние; без этого нельзя безопасно отправлять повторно. Успешные изменения существующего сообщения можно повторять. Сообщение ограничивается по длине; при переполнении указывается количество оставшихся строк. Клан показывается только при наличии проверенных данных; в текущей версии он не определяется.

В режиме MTProto статусы используют анимированные точки из набора `iconemoji1`. Для публикации нужен действующий Premium и сохранённая серверная Telegram-сессия. При недоступной сессии или отсутствии Premium публикация ждёт восстановления и не переключается на бота: Bot API может молча удалить custom emoji в канале.

## Состояние игры в канале

При включённой публикации через MTProto в том же канале создаётся отдельное постоянное сообщение с таблицей разделов. В ячейках только кастомные цветные точки: зелёная — есть подтверждённые успешные ответы, красная — подтверждены ошибки HTTP 500, белая — нет свежих подтверждённых данных. Это оценка наблюдавшихся запросов раздела, а не гарантия работы всех его функций. При режиме публикации ботом таблица не создаётся: Bot API может удалить кастомные emoji.

Наблюдения пассивные: используются физические ответы прямого соединения с игрой и проверенного TLS-туннеля Bridge. Кэш и внутренние ошибки Wiki не учитываются; новые запросы ради статуса не выполняются. Только HTTP 500 учитывается как ошибка, успешные ответы 2xx — как свидетельства работы. HTTP 501–599, отсутствие ответа, сетевые ошибки, ошибки авторизации и Telegram статус не меняют. Для красного статуса нужны три ответа 500 за две минуты с интервалом не менее 15 секунд. Для зелёного нужны два успешных ответа с интервалом не менее 15 секунд; после красного — по два для каждой подтверждённой группы маршрутов, в течение двух минут. Маршруты нормализуются до фиксированных категорий, идентификаторы и учётные данные не сохраняются. Из-за пассивного наблюдения некоторые разделы могут долго оставаться белыми. Подтверждение старше десяти минут становится белым, а предыдущий сбой сохраняется до подтверждённого восстановления.

Сообщение редактируется только при изменении статуса, не чаще одного раза за две минуты; состояние и ID сообщения хранятся отдельно от суточных рейдов. Зелёная точка использует проверенный ID из набора `iconemoji1`. Нужны те же Premium-сессия и права, что для сводки рейдов. Без переключения на бота или отправки запасного сообщения.

Если результат первой отправки неизвестен, повторная отправка блокируется даже после перезапуска. Оператору нужно проверить канал и остановить Wiki-автоматизацию, чтобы освободить её lease, затем в окружении с правильным `MADHOUSE_AUTOMATION_STATE_DIR` выполнить одну из команд:

```sh
node scripts/automation/reconcile-channel-game-status.mjs --delivered=TELEGRAM_MESSAGE_ID
node scripts/automation/reconcile-channel-game-status.mjs --not-delivered
```

Первую команду использовать только при обнаружении созданного сообщения, вторую — только если подтверждено, что сообщение не появилось. После запуска автоматизации найденное сообщение будет отредактировано, а при подтверждённой неотправке будет выполнена новая попытка. Команды сами ничего не отправляют в Telegram.
