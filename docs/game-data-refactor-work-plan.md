# Game data refactor: рабочий план

Цель: воспроизводимое локальное fake-окружение для проверки восстановления, данных и клиентского поведения. Production, игровые запросы и визуальные проверки не входят в текущий scope.

## Контракт и проверка: 30 октября 2026

Поддерживаемый контур — один Wiki service VPS с общим физическим координатором и signed IPC connector. Следующие разделы являются историческими срезами и не описывают состояние после этого изменения. Dev, standalone, операторские скрипты и установленный bridge-клиент не включены в утверждение о полном охвате VPS.

Ожидание приглашения и сверка неопределённого результата не расходуют этот бюджет; неопределённая мутация не отправляется повторно. Проверки: `scripts/automation/action-queue.test.mjs`, `tests/account-resource-versions.integration.test.mjs`.

`tests/business-resource-consumer.integration.test.mjs` монтирует настоящую карточку бизнеса и второй потребитель, проверяет совместное локальное чтение, обновление из сохранённого наблюдения и отписку. Тест проверяет состояние и число запросов, без визуальной проверки.

Воспроизводимое сравнение: `node scripts/dev/benchmark-game-data.mjs`. Скрипт извлекает исходники ревью `636a71e4` в временный каталог, использует одинаковый fake bridge, управляемые часы и реальный HTTP-обработчик очереди с SQLite. В этом сценарии до/после: игровых запросов 3/1, попаданий в сохранённый снимок 1/2, объединённых чтений 0/1, выдача сохранённого снимка 0/0 мс, подтверждение сохранённой команды при удерживаемом чтении 4000/0 мс; два конкурентных ответа были `409, 200` / `200, 200`. Это значения управляемых часов конкретного стенда, а не измерение production или обещание ускорения.

## Историческое состояние и приёмка

- Фаза 1 и общий VPS executor реализованы; исходный контракт и ограничения: `game-data-contract-phase-0.md`.
- Журнал bridge-попыток durable. Доверенный permit для read-only сверки queued `battle.attack` ограничен конкретным checkpoint и доказанной остановкой relay; исход игры и fence остаются unresolved. При неизвестном результате повтор мутации запрещён. Не считать закрытие WebSocket доказательством отсутствия поздней обработки.
- Глобальная блокировка неизвестной идентичности допускает только подтверждённый owner lease и строго заданные шаги авторизации через подписанный IPC. При отключённом публичном bridge можно включить `MADHOUSE_BRIDGE_RECOVERY_ONLY=1` на обоих VPS-сервисах: сохраняются внутренние проверки маршрута/lease и private IPC, публичные bridge HTTP/WebSocket и release не открываются. Режим требует существующие state и witness; чистое provisioning запрещено. Несовпадения хранения direct/bridge остаются открытыми.
- На старте goal локальный `main` чист; upstream `d4d5bb25`, `5180fc38`, `b19c778b` и `dfa3290d` интегрированы. Соседний bridge checkout содержит чужие изменения и не используется для записи.
- Локальный API автоматизации показывает адресный `recovery` (`clear`, `unresolved` или `unavailable`) без credentials и без игровых запросов. Для точно связанной остановленной попытки с работающим actor показывает возможность автоматической сверки; без доказательств или при конфликтующей попытке — недоступность. Проверка — `tests/automation-service.test.mjs`.
- Даже когда транспортный журнал уже завершён, actor с `reconciling` не отображается как `clear`; флаг автоматической сверки отражает доступность server heartbeat, а не подтверждённый результат.
- Завершившаяся локальная bridge-попытка больше не занимает обычный in-flight слот при неопределённом результате. Ограничение аккаунта и устройства остаётся отдельным fence: durable для записанных мутаций, временным для прочих неизвестных транспортных ошибок. Это ещё не разрешает recovery и не доказывает закрытие удалённых буферов; проверка — `scripts/game/direct-scheduler.test.mjs`.

Остальные и старые записи не связываются задним числом; без однозначного соответствия они остаются unresolved. ## Результаты и проверка

1. Восстановление: связать checkpoint и попытку, ограничить серверный permit, отдельно учитывать транспорт и результат; unresolved должен сохраняться и быть доступен локальному API. Проверить crash с работающим relay и fake game.
2. Данные: согласовать сохранённые ресурсы direct/bridge, freshness, invalidation и защиту от устаревших ответов; доказать нулевой игровой трафик strict readStored.
3. Клиент: устранить искусственное ожидание локальных команд, дублирование polling и устаревшие ответы, показывать состояние и возраст сохранённых данных.
4. Приёмка: fake transport и restart-сценарии, `npm run check`, connector build, профильные тесты и воспроизводимые инструкции. Визуальное тестирование и реальные запросы запрещены без отдельного разрешения.

## Следующий шаг

Локальное состояние готово к fake-тестированию по `game-data-fake-testing.md`. Для реального использования требуется отдельно выпустить и установить совместимый bridge; его тестовый checkout не проверяет полный комплект поставки. Старый клиент или потеря подтверждения остаются unresolved. Не разрешать мутации или снимать transport fence на основании таймаута, reconnect либо отрицательного чтения. Результат остаётся неизвестным даже после подтверждённой остановки relay, пока game evidence его не разрешит.

## Локальная пользовательская приёмка

Кандидат кода `d701017a8b626077519721e0c6cb536284554d52` исправляет ручной вход без первоначально установленной identity, показывает известный тип неподтверждённого queued-действия и добавляет изолированные Wiki-сессию, два synthetic account и сценарий запуска подписки из UI. Подробности браузерной проверки, счётчики, измерения и её ограничения: `game-data-user-acceptance.md`. Скриншоты лежат локально в `artifacts/game-data-acceptance/` и не входят в Git.

Состояние релизной подготовки: `launch/game-data-dependency-audit.md`, `launch/game-data-bridge-package.md`, `launch/game-data-release-acceptance.md`. Результат Fake приёмки не подтверждает production. Тестовый macOS пакет содержит relay из зафиксированного коммита, но сборочные исходники платформы взяты из незафиксированной рабочей копии; единый релизный bridge commit, версия и штатная подпись требуют отдельного решения владельца. Откат к образу без понимания нового durable-журнала небезопасен без отдельной проверки.
