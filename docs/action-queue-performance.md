# Очередь действий: проверка производительности

Измерение локально на fake game transport, без обращений к игре. Одинаковый тест `queued manual boss start writes a checkpoint and starts one fight`, по 20 независимых запусков Node для каждой версии. До: `service.mjs` из HEAD `fadb7693` при остальных общих модулях текущего рабочего дерева; после: текущая рабочая версия. Это сравнение изолирует изменение сервиса, а не воспроизводит полную сборку старой версии. Часы игрового сценария фиксированные, измерение — реальное время всего теста с созданием хранилища, запуском сервиса и проверкой результата; ожидание в тесте опрашивается раз в 25 мс. Это не измерение задержки игры или отдельных стадий.

| Вариант |   n | p50, мс | p95, мс | максимум, мс |
| ------- | --: | ------: | ------: | -----------: |
| До      |  20 |  1052.7 |  1059.8 |       1060.1 |
| После   |  20 |    61.4 |    66.2 |         78.3 |

Оба варианта проверяют один подтверждённый запуск боя. Отдельные замеры принятия, account queue, game executor, сетевого ответа, обновления UI и stop/cancel ещё необходимы; эти числа их не заменяют.

Дополнительное измерение в том же fake-сценарии (20 независимых запусков внутри каждого набора; опрос результата раз в 5 мс):

| Этап                                     | До p50 / p95 / max, мс      | После p50 / p95 / max, мс |
| ---------------------------------------- | --------------------------- | ------------------------- |
| Команда → ответ с сохранённым состоянием | 0,48 / 0,68 / 0,70          | 0,25 / 0,30 / 0,63        |
| Ответ → наблюдение fake POST             | 1009,73 / 1011,83 / 1013,53 | 5,34 / 6,64 / 6,69        |
| Команда → наблюдение завершённого job    | 1010,34 / 1012,33 / 1014,11 | 5,65 / 6,96 / 7,06        |

В обоих наборах за сценарий было по три вызова fake transport (p50, p95 и максимум). Измерение POST включает погрешность опроса до 5 мс и не выделяет ожидание account queue и game executor; они требуют отдельного теста. Замер подтверждённого отображения UI и stop/cancel также остаётся открытым.

Отдельная последовательная цепочка `createAccountQueue` → `createDirectExecutor` → fake transport, по 20 запросов на набор, без конкуренции и pacing. Fake transport отвечает после искусственных 5 мс. Это измерение уровней исполнителя, не сетевой транспорт и не тот же полный UI-сценарий:

| Этап                     | До p50 / p95 / max, мс | После p50 / p95 / max, мс |
| ------------------------ | ---------------------- | ------------------------- |
| Ожидание в account queue | 0,012 / 0,026 / 6,685  | 0,008 / 0,017 / 0,175     |
| Ожидание в game executor | 0,029 / 0,052 / 0,591  | 0,029 / 0,058 / 0,556     |
| Fake запрос → ответ      | 5,682 / 5,748 / 5,896  | 5,666 / 5,687 / 5,687     |

Каждый набор вызвал fake transport 20 раз на 20 команд. Открытым остаётся замер подтверждения → UI и устойчивого stop/cancel; сравнивать эти числа с production нельзя.

Отдельный fake-сценарий с удерживаемой первой мутацией: отмена второй, ещё не отправленной команды → чтение `cancelled` из durable-хранилища. По 20 повторений: до p50 0,339 мс, p95 0,462 мс, максимум 0,602 мс; после p50 0,334 мс, p95 0,408 мс, максимум 0,455 мс. В каждом наборе отправлено 20 первых мутаций и ни одной отменённой. Это замер server-side cancel ожидающей задачи, а не сетевой задержки кнопки или остановки уже отправленной операции.

Для ручного боя и экипировки клиент планирует одну проверку сохранённого серверного состояния через 250 мс после принятия; далее используется существующий интервал обновления. Это серверное чтение состояния, а не дополнительный запрос к игровому API. Проверка задержки подтверждения до фактического обновления UI пока требует отдельного измерения.

В отдельной проверке реального клиентского facade с fake сервером 20 независимых сессий работали параллельно; серверный результат становился подтверждённым сразу после enqueue, затем измерялось обновление подписанного client state. До p50 2002,29 мс, p95 2002,41 мс, максимум 2002,43 мс; после p50 251,42 мс, p95 251,49 мс, максимум 251,50 мс. На сессию приходилось два чтения server state, включая начальное; игровые запросы не выполнялись. Это не измерение отрисовки в браузере.
