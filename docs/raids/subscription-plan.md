# Подписки на рейды

## Источники и обнаружение

Публичное расписание и личные приглашения показываются в одном списке карточек. Заголовок публикации и ссылка на её источник из списка убираются. Личные наблюдения принадлежат только аккаунту и не попадают в публичное расписание или каталог.

Сервер опрашивает входящие приглашения, пока доступна действительная сессия. Для обнаружения серии хранит не более двух часов наблюдений: ключ — проверенные идентификаторы ведущего и босса, уникальность — идентификатор боя. Три разных боя за последние два часа и действующее приглашение на ту же пару обозначают вероятный рейд. Повторное чтение одного приглашения не увеличивает счётчик. Записи ограничиваются по возрасту и количеству; недоступность API не считается окончанием серии. Личные сведения и сроки хранения должны быть отражены в интерфейсе.

Подписка из расписания может ожидать приглашения по точному имени пользователя и однозначно найденному боссу. До первого подходящего приглашения она не выполняет игровых действий; при получении сервер фиксирует проверенный числовой идентификатор ведущего и далее принимает приглашения только от него. Отображаемый ник без проверенного имени пользователя не используется для сопоставления. Если босса или имя пользователя установить однозначно нельзя, карточка остаётся справочной.

## Подписка и исполнение

Подписка задаёт конкретную пару ведущий–босс, хранится сервером для проверенного аккаунта и отображается на общей карточке. У неё есть явная отмена. При новом доступном приглашении этой пары подписка получает приоритет на безопасной границе: текущая отправленная операция сначала подтверждается или переходит в неопределённое состояние; текущий бой не прерывается. Неопределённая операция блокирует новые изменяющие запросы до сверки. Предыдущие цели, лимиты, счётчики и пользовательские настройки не сбрасываются.

Пока серия активна, сервер принимает только свежие приглашения выбранного ведущего и босса, подтверждает конкретный бой и запускает существующий безопасный автобой. Используются существующие настройки лечения и лимиты; автоматическая покупка не включается без разрешения. Если десять минут после последнего подтверждённого приглашения нет нового, предыдущая цель возобновляется на безопасной границе. Отсчёт не должен истекать из-за ошибки чтения игры: при сбое подписка ждёт восстановления и актуальной проверки. Новое приглашение после возобновления снова повышает приоритет. Остановка подписки не отменяет предыдущую цель.

Нужен единый серверный координатор приоритетов для работы, бизнеса, автобоя и собственного рейда: приостановка должна сохранять намерение, а не вызывать существующие stop-методы, которые его удаляют. Переходы и checkpoints сохраняются до запросов; после рестарта состояние восстанавливается и сверяется с игрой без повторной отправки неопределённой операции. Работники и ручные действия используют общую блокировку аккаунта и проверяют право на отправку непосредственно перед запросом.

## Реализация и проверка

1. Подтвердить контракт идентификаторов и состояния приглашений на доступных ответах; не использовать ник как идентификатор. Добавить ограниченный журнал наблюдений и тесты дедупликации, срока хранения, изоляции аккаунтов и сбоев.
2. Добавить сохраняемую подписку и координатор, отдельные состояния ожидания, боя, приостановки и возобновления. Проверить восстановление после рестарта и конкурентные команды для каждого типа цели.
3. Объединить публичные и личные карточки, добавить управление подпиской и понятные причины недоступности, убрать заголовок и ссылку источника. Использовать существующий UI Kit.
4. Проверить на фальшивом игровом транспорте ошибки чтения, потерянные ответы POST, идентичные и чужие приглашения, завершение боя, истечение окна, отмену, перезапуск и отсутствие повторного расходования. Выполнить полные обязательные проверки релиза.
5. Выпустить проверенный коммит и подтвердить состояние сервисов. В проде проверить доступные чтения и контролируемую подписку с заранее проверенными настройками; отдельно зафиксировать сценарии, которые не удалось воспроизвести, особенно потерянный ответ и реальную ошибку игры.
